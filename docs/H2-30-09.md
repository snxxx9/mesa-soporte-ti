## 1. Alcance v1.0

La aplicación web permitirá registrar y controlar solicitudes de soporte informático desde que se crean hasta que se cierran.

### Funciones incluidas

- Registrar una solicitud con solicitante, título, descripción, categoría y prioridad.
- Generar automáticamente un identificador y una fecha de creación.
- Mostrar un listado con estado, prioridad y responsable.
- Asignar o cambiar el responsable de un ticket.
- Cambiar el estado entre Nuevo, En proceso, Resuelto y Cerrado.
- Filtrar por estado, prioridad o categoría.
- Mostrar un resumen con el total de solicitudes y la cantidad por estado.
- Guardar usuarios, categorías, tickets y cambios relevantes en SQLite.
- Mantener un historial cuando cambie el estado o el responsable.
- Validar campos obligatorios y valores permitidos.
- Mostrar mensajes claros cuando exista un error de ingreso.

### Fuera del alcance

Para no agrandar demasiado el proyecto, se mantienen fuera del MVP:

- Inicio de sesión y autenticación.
- Chat interno.
- Correos o notificaciones automáticas.
- Archivos adjuntos.
- Aplicación móvil.
- Administración completa de usuarios.
- Reportes avanzados o exportación a Excel/PDF.

### Reglas que quedan definidas

- Prioridades: Baja, Media y Alta.
- Estados: Nuevo, En proceso, Resuelto y Cerrado.
- Categorías iniciales: Hardware, Software y Conectividad.
- Todo ticket nuevo parte en estado Nuevo.
- Un ticket puede crearse sin responsable.
- El solicitante y el responsable se seleccionan desde usuarios de prueba.
- Los cambios de estado o responsable quedarán registrados en el historial.
- No vamos a agregar funciones nuevas si ponen en riesgo las fechas de H3, H4 o la entrega final.

## 9. Arquitectura preliminar

La arquitectura queda definida de la siguiente forma:

**Navegador → Flask → SQLite**

- HTML y CSS mostrarán las pantallas.
- Flask recibirá formularios, hará validaciones y ejecutará las consultas.
- SQLite guardará usuarios, categorías, tickets e historial.
- Git y GitHub mantendrán el historial del código.
- GitHub Projects se utilizará para controlar las tareas y fechas.

Elegimos esta estructura porque es pequeña, no necesita un servidor de base de datos aparte y alcanza para cumplir el MVP dentro del tiempo disponible.
